# 上下文与 Token

上下文窗口决定一次请求可以携带多少信息。真正的工程问题不是“塞入越多越好”，而是如何让与当前任务最相关的约束、接口和证据保持可见。

## 上下文分层

1. **任务层**：目标、验收标准和不可违反的限制。
2. **仓库层**：目录结构、现有模式和运行命令。
3. **实现层**：当前文件、依赖关系和相关测试。
4. **反馈层**：构建输出、测试结果和用户反馈。

## 实践建议

每次交互都优先提供能改变决策的上下文；对于长文档，保留结构化摘要和稳定链接，而不是重复粘贴全部内容。

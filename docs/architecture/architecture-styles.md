# 架构风格

架构风格描述的是一类系统在组件、连接器和约束上的共同组织方式。它帮助我们在设计早期快速缩小方案空间。

## 常见风格

| 风格 | 关注点 | 常见场景 |
| --- | --- | --- |
| 数据流 | 数据如何经过一组处理步骤 | 批处理、管道与过滤器 |
| 调用返回 | 控制权如何在模块间传递 | 分层、主程序与子程序 |
| 事件驱动 | 组件如何通过事件解耦 | 消息系统、异步流程 |
| 仓库 | 多个组件如何共享数据 | 数据库、黑板系统 |

## 选择方法

先描述业务的主要变化方向，再检查一致性、延迟、吞吐和团队边界等约束。风格不是模板答案，而是做取舍时的共同语言。

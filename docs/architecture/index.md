# 架构知识

架构不是一张图，而是一组关于边界、职责、约束和演进的决策。本专题从概念入手，再回到真实系统中的权衡。

## 学习路线

1. 先理解架构风格、边界和系统分解方式。
2. 再用 4+1 视图、4A 架构和质量属性描述系统。
3. 最后结合分布式系统与案例分析验证设计。

## 基础框架

- [架构风格](/architecture/architecture-styles)：理解数据流、调用返回、事件驱动和仓库等风格。
- [架构视图](/architecture/architecture-views)：用多个视角描述同一个系统。
- [质量属性](/architecture/quality-attributes)：把可用性、性能、可维护性变成可讨论的约束。

## 记录原则

每篇笔记尽量说明问题背景、关键约束、方案权衡和验证方式。

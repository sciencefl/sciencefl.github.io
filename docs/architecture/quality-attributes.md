# 质量属性

质量属性是架构决策的约束来源。讨论性能时要说明延迟和吞吐，讨论可用性时要说明故障范围、恢复目标和降级路径。

## 记录模板

- **目标**：希望系统具备什么能力。
- **场景**：在什么负载、故障或变化下观察它。
- **度量**：用什么指标判断是否满足。
- **策略**：通过哪些结构和机制实现。
- **代价**：引入了哪些复杂度、成本或维护负担。

## 一个完整的判断

不要只写“系统要高性能”，而要写成“在 95 分位延迟小于 200ms、并发 5000 时，核心读请求保持成功率 99.9%”。可度量的目标才能指导设计和验证。
